# Отдельный лид на каждую открытую линию

## Что делает код

Файл [`include_ol_line_leads.php`](include_ol_line_leads.php):

- ловит привязку OL-чата к **лиду**;
- если на этом лиде уже есть чат с **другой** открытой линией → создаёт **новый** лид и переносит текущий чат;
- сообщения в уже привязанном чате / активность на **сделке** → новый лид **не** создаётся.

## Подключение (обязательно)

В **существующий** `bitrix/php_interface/init.php` (не затирая его) добавь в конец:

```php
$olLeads = $_SERVER['DOCUMENT_ROOT'] . '/local/custom_chat/include_ol_line_leads.php';
if (is_file($olLeads)) {
    require_once $olLeads;
}
```

Залить:

- `/local/custom_chat/include_ol_line_leads.php`
- `/local/custom_chat/ol_line_leads_run.php` (ручной прогон)

После заливки: очистить кеш Bitrix. Агент `olLineLeadsAgent();` зарегистрируется сам (раз в 60 сек).

## Ручная проверка уже склеенного лида

Под админом открой:

`https://crm.artflowers.kz/local/custom_chat/ol_line_leads_run.php?leadId=331574`

В ответе будут чаты/линии (`LINE_ID` / `KEY`) и действия split.

Если раньше было `no conflict` при двух чатах с `LINE_ID: 0` — это green-api/ChatApp без `CONFIG_ID`. Теперь identity берётся из:
`CONFIG_ID` → `USER_CODE` → `ENTITY_ID` → хинт из TITLE/SUBJECT («Уральск Райхан» / «Уральск Мария»).

Debug meta: `?leadId=331574&debug=1`

Логи: `AddMessage2Log` / тег **`ol_line_leads`**.

## Шаг 1 — настройки ОЛ (рекомендуется)

Для **каждой** линии (Райхан, Мария, …):

**Контакт-центр → Открытые линии → [линия] → CRM**

- Создание лида / сделки — как нужно бизнесу (обычно лид).
- По возможности **ослабить автопоиск** «найти клиента и привязать к существующему» — иначе Битрикс сначала клеит к старому лиду, а наш код уже **разлепляет**.
- ChatApp / Green-API: галка «Создавать чат ОЛ при исходящих» — **не про лиды**, только про исходящие сессии/ботов. На split лидов не влияет.

## Тест

1. Два входящих WhatsApp с **разных** линий (или тестовые сессии) с одним и тем же клиентом/телефоном.
2. Ожидание: **два разных лида**, на каждом свой «Чат с клиентом».
3. Кнопка **WhatsApp чат** на каждом лиде открывает свой диалог.
4. Повторные сообщения в том же чате / лид уже в сделке — **без** новых лидов.

При конвертации лида в сделку чат ОЛ сам в таймлайн сделки **не** переезжает (штатный Битрикс). Код вешает binding на сделку (`OnAfterCrmDealAdd` / `OnAfterCrmLeadConvert`). Уже созданную сделку починить:

`/local/custom_chat/ol_line_leads_run.php?dealId=215072`

Старые лиды с двумя чатами код **не** чистит задним числом.

## Таймлайн лида/сделки (чат ОЛ)

Вкладка/кнопка локального приложения ≠ запись в таймлайне. В ленте нужен activity `IMOPENLINES_SESSION` (как штатный «Чат с клиентом»).

- На **новых** лидах чат появляется сам, если OL/CRM создал activity.
- На **старых** — вручную:

```
/local/custom_chat/ol_line_leads_run.php?leadId=332315&timeline=1
```

Явный чат: `&chatId=XXXX`. Только админ. Ответ JSON: `activityId`, `chatId`, `created`/`bound`.

Перенос на сделку по-прежнему: `?dealId=…` / `?dealId=…&prune=1`.
